# 0) Quick recap (what we're building)

* Plane: **16×16 pixels** (17 colors: 16 + transparent).
* We group pixels into **64 leaves** of **2×2**.
* Each 2×2 is pre-baked as a tile in a **1024×1024 atlas** (because (17^4=83{,}521) → needs a 289×289 grid of tiles; we pad to 1024).
* Runtime state per leaf is just a **tileId ∈ [0..83,520]**.

To fit in **≤32 floats**:

* Keep a **palette of up to 16 tileIds** → **16 floats** (`tp0..tp15`).
* For each of the **64 leaves**, store a **4-bit index** into that palette (0..15).

  * Pack **6 indices per float** (6×4 = **24 bits**, exact in a 32-bit float) → **11 floats** (`leaf_idx_f0..f10`).

Total: **27 floats**. (Grid dimensions 289×289 are hardcoded in render controllers.)

# 1) Property layout (names and counts)

**Tile palette (16 floats)**

**Leaf indices (11 floats)**

# 2) TileId encoding/decoding (script side)

For a 2×2 leaf with colors (TL,TR,BL,BR \in [0..16]):

```ts
// encode (integer math)
function encodeTileId(TL: number, TR: number, BL: number, BR: number): number {
  return TL + 17*TR + 17*17*BL + 17*17*17*BR; // 0..83520
}

// decode (if you ever need to on script side)
function decodeTileId(tileId: number) {
  const TL =  tileId % 17;
  const TR = ((tileId / 17)      | 0) % 17;
  const BL = ((tileId / (17*17)) | 0) % 17;
  const BR = ((tileId / (17**3)) | 0) % 17;
  return {TL, TR, BL, BR};
}
```

# 3) Build the **palette** and **leaf indices** (script side)

> **Note**: This packing logic runs **server-side** in the behavior pack (e.g., TypeScript/JavaScript). The packed data is then written to entity properties that the resource pack reads. The resource pack's entity file (generated by `gen_painting.entity.js`) pre-calculates palette indices from these packed properties.

```ts
type Leaf = { tileId: number }; // 64 entries, row-major
type PalettePack = {
  used: number;        // 1..16
  tp: number[];        // length 16 (fill unused with 0)
  idxFloats: number[]; // 11 floats, each storing up to 6 nibbles
};

// Build a palette of up to 16 most-frequent tileIds, map leaves to 4-bit indices.
function buildPalette(leaves: Leaf[]): PalettePack {
  // 1) frequency count
  const freq = new Map<number, number>();
  for (const {tileId} of leaves) freq.set(tileId, (freq.get(tileId) ?? 0) + 1);

  // 2) take top 16 by frequency (or fewer)
  const sorted = [...freq.entries()].sort((a,b)=>b[1]-a[1]).slice(0,16);
  const palette = sorted.map(([id])=>id);
  const used = palette.length;
  // fill to 16 for stable Molang lookups
  while (palette.length < 16) palette.push(0);

  // 3) map tileId -> palette index (0..used-1). If a leaf’s tileId not present,
  //    pick nearest by simple heuristic; here we map to index 0 as fallback.
  const indexOf = new Map<number, number>();
  for (let i=0;i<used;i++) indexOf.set(palette[i], i);

  const indices: number[] = new Array(64);
  for (let i=0;i<64;i++) {
    const id = leaves[i].tileId;
    const idx = indexOf.has(id) ? (indexOf.get(id) as number) : 0; // fallback
    indices[i] = idx; // 0..15
  }

  // 4) pack 6 nibbles per float (big-endian within the 24 bits)
  const idxFloats: number[] = [];
  for (let base=0; base<64; base+=6) {
    let acc = 0;
    let count = Math.min(6, 64-base);
    for (let k=0;k<count;k++) {
      acc = (acc << 4) | (indices[base+k] & 0xF);
    }
    // shift up to always use the lowest bits: NOT required;
    // decoding uses powers of 16 to peel from least-significant end.
    // We will decode from the RIGHT (LSBs), so reverse pack for convenience:
    // Repack so that indices are at nibble positions 0..5 (LSB..)
    let lsbAcc = 0;
    for (let k=0;k<count;k++) {
      lsbAcc |= (indices[base+k] & 0xF) << (4*k);
    }
    idxFloats.push(lsbAcc); // <= 0xFFFFFF, safe as float exact integer
  }

  return { used, tp: palette, idxFloats };
}
```

> If you **must** preserve exact visuals when >16 distinct tiles are present, use an **overflow strategy**:
>
> * Split into two layers (two entities, each 32 floats).
> * Or “dynamic swap”: when a new tile appears, inject into palette (evict least-used) and update affected leaves over a couple frames.

const powerValues = [1, 16, 256, 4096, 65536, 1048576]; // 16^0 through 16^5

# 8) Updates at runtime

When pixel(s) in a leaf change:

1. Recompute its **tileId**.
2. If this tileId is **already in the palette**, just update that leaf's **4-bit index** and rewrite **one of the 11 floats**:

   * Find which `leaf_idx_fN` holds it: `N = floor(leafId / 6)`.
   * Replace the nibble at position `leafId % 6`.
3. If it's **not in the palette** and palette has space (< 16 entries): append to palette and set the index.
4. If palette is **full (16)**: choose an overflow strategy

   * Replace least-frequent palette entry and rewrite affected leaves’ indices (rare).
   * Or split into layers (two entities).

Packing/unpacking nibbles in a 24-bit int:

```ts
// set nibble at position p (0..5) inside a 24-bit integer
function setNibble24(acc: number, p: number, val: number): number {
  const mask = ~(0xF << (4*p)) & 0xFFFFFF;
  return (acc & mask) | ((val & 0xF) << (4*p));
}

// get nibble
function getNibble24(acc: number, p: number): number {
  return (acc >> (4*p)) & 0xF;
}
```

# 10) Practical notes / pitfalls

* **Float precision**: Never exceed 24 bits per packed float (we don’t—24 exactly).
* **Atlas sampling**: use **nearest/point** filtering; disable mipmaps or add 1-px gutters + center sampling if mips are unavoidable.
* **UV control**: plan early how you’ll **apply (tileX,tileY)** to leaf UVs within Bedrock’s limitations. If you can’t offset UVs dynamically, convert `tileId → small slot (0..K-1)` and pre-UV K slots per leaf (K=8/16).
* **>16 distinct tiles**: decide now: **approximate**, **layer**, or **dynamic swap**.
